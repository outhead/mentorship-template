## Основные команды

### 1. «Сгенерируй саммари для сессии N»

**Входные данные:**
- `sessions/session-NN/transcript.md` — транскрипция встречи
- `commitments.md` — актуальные договорённости
- `assets/templates/session-template.html` — шаблон
- Прошлые саммари в `sessions/session-XX/index.html` (для преемственности)

**Что делаешь:**
1. Прочитай транскрипцию
2. Прочитай текущий `commitments.md`
3. Определи, какие старые договорённости были упомянуты → обнови их статус (done / in_progress / still todo)
4. Выдели новые договорённости из текста → добавь в `commitments.md` с датой постановки
5. Обнови `commitments.md` (это главный источник правды)
6. Сгенерируй `sessions/session-NN/index.html` на базе шаблона, наполняя его:
   - Ключевыми результатами с прошлой сессии (что выполнено из `commitments.md`)
   - Фокусом на компетенциях (что обсуждали)
   - Целями на ассессмент Senior (если упомянуто)
   - Договорённостями (таблица из `commitments.md`, отфильтрованная: новые + активные)
   - Рекомендациями от Егора
   - Алертами «на что обратить внимание» (энергия, риски)
   - Датой и ссылкой следующей сессии
7. Обнови `index.html` в корне (список сессий) — добавь карточку новой сессии
8. Верни мне summary того что поменялось

**Важные правила генерации саммари:**
- Сохраняй визуальный стиль шаблона — тёмная тема, те же цвета, типографика
- Номер сессии и тема — в теге «Сессия #N» и заголовке
- Статусы договорённостей: ✓ done / → в работе / ○ todo
- Цветовые метки ролей: Егор — фиолетовый, Анна — зелёный, Оба — жёлтый
- Тон в алертах — мягкий, поддерживающий, с конкретными советами
- Названия файлов — `sessions/session-NN/index.html` (NN с ведущим нулём)
- Дата всегда — в формате «N месяца, HH:MM»

### 2. «Подготовься к сессии N»

**Что делаешь:**
1. Прочитай `commitments.md` — выдели всё, что в статусе `todo` или `in_progress`
2. Прочитай последнее саммари — выдели тему, ключевые результаты, алерты
3. Прочитай `mentee-profile.md` — напомни контекст
4. Выдай план встречи:
   - Что проверить по прошлым договорённостям (чьи, статус)
   - На что обратить внимание (незакрытые алерты, риски выгорания)
   - Предлагаемые темы для обсуждения
   - Что должен подготовить Егор до встречи (свои обещания из `commitments.md`)

### 3. «Обнови commitments» / «Закрой договорённость X»

Ручное редактирование списка. Поддерживай формат структурированным (см. ниже).

### 4. «Что мы обсуждали про [тему]»

Поиск по всем транскрипциям и саммари. Цитата + ссылка на сессию.

## Формат commitments.md

```markdown
# Договорённости

## Активные

### Анна

- **[session-02] Выпросить контакт аналитика** `todo`
  Узнать, какие метрики команда планирует. Предложить обмен: рассказать о продукте → получить данные.

- **[session-02] Прикрепить скрины метрик** `todo`
  Еженедельно фиксировать состояние дашборда по воронке.

### Егор

- **[session-02] Найти статьи «до/после»** `todo`
  Кейсы изменений интерфейса и влияния на метрики (Альфа-Банк, Хабр). Подборка через Grok.

## Закрытые

- **[session-01 → session-02] ✓ Завершить CJM-пилот** (Анна) — презентовано продакту и команде
- **[session-01 → session-02] ✓ Запустить лендинг** (Анна) — внешний лендинг в проде за 2 недели
```

## Формат transcript.md

Любой — свободный текст или диалог. Можно кидать сырую транскрипцию от Zoom/другого сервиса. Ты сам разберёшься.

## Правила по коммитам

После генерации саммари предлагай команду:
```bash
git add . && git commit -m "Session N: [тема]" && git push
```

## Что НЕ делать

- Не меняй шаблон `session-template.html` без моей команды
- Не удаляй старые договорённости — только переноси в «Закрытые»
- Не выдумывай информацию которой нет в транскрипции
- Если в транскрипции что-то непонятно — спрашивай у меня, а не додумывай
